## Style Guidelines

Code that works is only half the job. The other half is making it easy for the next person
to read, and that's what style guidelines are for.

For the official word on coding style, consult the
[Style Guide (PEP 8)](https://peps.python.org/pep-0008/). It's the standard that most Python
code follows, and it covers far more than this lesson does.

---

Some specific rules to which our team subscribes include:

* All indents should be four spaces
* Limit code to 79 characters per line. That's the PEP 8 rule. At DataBank, we use a
  120-character limit (usually), because our code is easier to read in wider windows.
* Limit comments to 72 characters per line.<br>
  Yes, I have violated this rule in many of the lesson files.
* Use blank lines to group functionally related sections of code
  (but not to excess)

The 79-character limit is the PEP 8 rule. The 120-character limit is a team choice, and it's
the one we use. When you read a style guide, you'll often find a rule like this that a
particular team has adjusted. Know the standard, and know your team's version of it.

---

Pylint, which is already set up in the course's VS Code settings, flags many of these issues
as you type. Pay attention to its warnings, even when the code runs fine.
